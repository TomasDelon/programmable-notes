# ADR-003: Tauri preview authority and Linux resource boundary

Status: implemented prototype; native build/runtime BLOCKED in this cloud. Do not interpret policy tests or Chromium as native security validation.

The existing compiler/browser engine is retained. Tauri 2 adds an editor window (`editor`) and a separate executable process for each preview. No document JavaScript executes in the editor's native webview. On native builds React uses `NativePreview`; the browser keeps its existing iframe path. Preview artifacts are generated by the same compiler and bounded to 4 MiB at the native command boundary.

## Native authority

Tauri's app manifest explicitly lists `start_preview`, `stop_preview`, and `host_probe`, so these commands participate in generated ACL checks. The only configured capability is local `editor`, matching only the editor window/webview; it grants only these three commands. No wildcard, remote origin, core-default, event, window-creation, filesystem, shell, HTTP, opener, or sidecar plugin permission is installed. The harmless host_probe sentinel is a registered-command positive control, permitting tests to distinguish actual denial from an absent bridge/command.

Every handler additionally checks the actual calling webview label and a native child-mode flag. A preview child fails this guard even if a future capability were mistakenly broadened or a caller requested label `editor`. The preview child registers the same commands so tests can probe real denials, but receives no capability. Its webview is ephemeral/incognito, has a navigation allowlist and an opaque-origin `sandbox="allow-scripts"` iframe. The outer shell has the parent navigation/network policy; the inner artifact retains its hash-authorized script CSP. The editor has a distinct CSP: self-hosted scripts plus wasm-unsafe-eval for the pinned compiler, blob workers only, no blob scripts or JavaScript unsafe-eval. The no-capability child context omits Tauri’s editor CSP header and instead uses the committed outer-shell meta policy and the dynamic artifact’s strict hash CSP. Tauri would otherwise add editor script hashes to the outer shell, whose inherited script-src rejects new document hashes. The outer shell must not set script-src none, which would inherit into srcdoc and prevent legitimate React execution. This per-process policy split needs actual WebKitGTK verification; it does not disable the inner artifact checks or grant child IPC authority. Only the trusted native initializer receives the serialized artifact; no eval of document code occurs in the outer shell.

The native preview grants no host bridge to author code. Absence of APIs is not the proof: real WebDriver tests call registered Tauri commands from the preview webview, require permission denial, then exercise an actual React counter and DOM/storage denial in the inner iframe. Filesystem/shell/HTTP plugin probes document an intentionally absent plugin surface, not a native plugin ACL audit.

## Resource lifetime

On Linux only, the host launches its own executable under a systemd user service with MemoryMax=512 MiB, MemorySwapMax=0, CPUQuota=25% of one CPU, TasksMax=128, RuntimeMaxSec=60, TimeoutStartSec=5, TimeoutStopSec=1, KillMode=control-group, OOMPolicy=kill, NoNewPrivileges=yes, and PrivateNetwork=yes. There is no shell expansion, author-controlled executable/argument, automatic dependency install, or fallback to an unrestricted child. Only an explicit graphical-environment allowlist is forwarded. systemd's own inherited user-manager environment is not claimed sanitized of all ambient authority.

The child blocks reading stdin before creating WebKit. Before sending an artifact, the supervisor waits for an active unit and reads its ControlGroup's actual cgroup v2 memory.max, memory.swap.max, cpu.max and pids.max. Missing/delegation-disabled controllers, unbounded or excessive values, absent user manager, namespace failures, startup failures, unsupported OS, or oversized artifacts reject launch. Requested unit properties alone are insufficient evidence. Stop targets the systemd unit, covering WebKit descendants rather than just systemd-run; collected/not-found units are treated as stopped. Failed stop retains the unit and prevents replacement. Exit requests stop; the independent service wall-time limit is a backstop if the editor crashes.

These are enforced policies only when the Linux tests verify their effective behavior. Native resource limits are not yet measured in this cloud; chosen budgets may need tuning after normal WebKit startup is measured. CPUQuota throttles rather than terminating a loop; RuntimeMaxSec and Stop provide termination. Browser code cannot request larger limits. Whole-service OOM/stop/restart and descendant cleanup must be tested on a delegated Linux desktop. This does not sandbox arbitrary compromised native code: same-user DBus, browser vulnerabilities, GPU/device access and other ambient OS authority need a broader OS threat review.

## Rejected alternatives and remaining gates

A second webview in the editor process does not establish independent OS resource accounting. Killing only an iframe or launcher PID does not reliably terminate WebKit descendants. RLIMIT_AS is unsuitable as the primary limit because WebKit reserves large virtual address regions and uses multiple processes. Property-only systemd checks do not establish effective delegated cgroup controls. None is used as a silent fallback.

`tauri dev` can run the editor, but native preview explicitly rejects that mode: PrivateNetwork prevents the preview from reaching Vite's loopback server. Test embedded assets with custom-protocol instead; do not remove network isolation for convenience. Non-Linux preview fails closed until an equivalent supervisor is implemented and validated.

The security-test Cargo feature adds only shell selection flags for WebDriver (`--security-editor`, `--security-probe`); it adds no permissions and does not bypass handler authorization. The preview-probe shell runs without the supervisor solely to test WebKit/IPC in WebDriver; that session is not evidence of resource containment. Never ship test-feature binaries as an approved security release.

Native compilation/runtime, capability denial, incognito storage separation, srcdoc compatibility, cgroup enforcement, network namespace behavior, memory-pressure failure and reliable restart are release gates, not inferred successes. Visual editing remains deferred.
