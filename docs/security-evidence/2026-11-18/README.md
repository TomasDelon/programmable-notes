# Milestone 3: production Linux evidence

Implementation commit: `0e7b332` (native store introduced in `904d771`).

This record distinguishes the optimized, installed production package from the prior milestone's debug/test-feature evidence. Tests use a disposable Ubuntu 24.04 full-system VM, not the outer Codex container. No public release, merge or PR readiness change is authorized.

## Environment and artifacts

The guest uses Ubuntu 24.04.5, Linux 6.8.0-149, systemd 255, WebKitGTK 2.52.6, GTK 3.24.41, cgroup v2 with delegated cpu/memory/pids, ordinary UID 1000, authenticated Xvfb/Openbox and software rendering. QEMU TCG provides four virtual CPUs and 8 GiB RAM; KVM and a physical GPU are unavailable. The baseline has `kernel.unprivileged_userns_clone=1` and `kernel.apparmor_restrict_unprivileged_userns=1`. The separate `kernel.apparmor_restrict_unprivileged_unconfined` value was initially 0; its additional tightened-mode desktop check is recorded separately. The package's own AppArmor profile permits its bubblewrap namespace use; a separately reviewed administrative executor opt-in enables actual PrivateNetwork. That executor policy is not installed by the package and affects other systemd service descendants.

The package is built with `tauri build --bundles deb --features custom-protocol -- --locked`, optimized release mode, without `security-test`. The external fixture wrappers add no app permission/API and do not alter its executable. Direct WebDriver preview probes establish IPC/profile behavior only; supervised automation-disabled children establish resource behavior separately.

## Verified findings and fixes

- **Silent network-isolation fallback:** without the administrator executor opt-in, systemd logged that PrivateNetwork was skipped yet started the unit successfully. The hardened supervisor refused because the actual network namespace matched the editor's, exited 2, stopped the group and delivered no author payload sentinel. Global Ubuntu restrictions and the distribution profile stayed intact. The initial FUSE-output inspection abort is retained separately, not counted as a pass.
- **WebKit process sandbox absent by default:** both normal and ephemeral contexts reported false. The pre-fix installed application had WebProcess Seccomp=0 and shared namespaces. After the Wry creation-path fix, the unchanged administrative observer required and observed NoNewPrivs=1, Seccomp=2 with a filter and separate mount/network/PID/user namespaces. The pre-fix assertion failed and the post-fix assertion passed. WebKit's NetworkProcess remains outside that engine sandbox; the preview service still constrains it through private networking and cgroups.
- **Late compiler initialization:** a timed-out WASM initialization could start a new document worker afterwards. A failing unit test demonstrated this; the deadline now invalidates the build before late initialization returns.
- **Editor callback/close races:** stale editor callbacks could target a newly selected document, and typing while close IPC was pending could disappear. Regressions failed before the fixes and passed afterwards. Newer input remains an unsaved buffer; a released native grant is not retained.

## Native filesystem observations

The installed production application has exercised real GTK pickers and actual on-disk files: picker cancellation, forged-grant refusal from the editor, exact UTF-8/Unicode/CRLF bytes, atomic inode replacement, mode 0640 preservation, read-only error without disk/buffer loss followed by retry, external-change conflict, cancelled reopen, Save As preserving both versions, and reopening updated disk content. The complete optimized-package persistence suite subsequently passed, including POSIX ACL preservation and two real Counter clicks plus the newly edited button. Earlier runs passed filesystem checks but failed the external preview deadline; those failed runs remain evidence, not whole-suite passes.

A test-driver failure initially saved `saved-as.mdx.mdx`: GTK selected only the filename stem. Explicitly selecting the whole location field fixed the external driver; the application's source bytes were not changed to make the test pass. The later preview/AT-SPI timeout was a test-budget failure: the original Counter became ready around 50 seconds after the startup reply under TCG. Both deferred and immediate polling with a 55-second external readiness deadline reached Count: 2 before the unchanged 60-second service expiry. No early-query deadlock or PID-binding defect was established. The release now minifies its embedded React runtime; Vite cannot minify JavaScript embedded through a raw string import.

The Rust store's 18 real-filesystem tests cover metadata/xattrs, atomic readers, conflicts, race cases, parent rename anchoring, hardlinks, invalid filenames/encoding, symlink/FIFO refusal, bounds and authorization revisions. These are backend tests, not a claim that all those cases were driven through GTK.

## Scope and remaining gates

A successful compile, package inspection or installation is never a native security pass. Physical GPU/Wayland/other distributions are untested here. The application does not provide complete hostile-native-code containment: authenticated X11, session DBus, native browser exploits, devices and deliberate cgroup escape after native compromise remain outside the demonstrated JavaScript boundary. Same-user noncooperating writes can race the last file conflict check; unsaved text has no crash journal. Directory-fsync failure reporting is implemented but not fault-injected.

See [reproduction contract](../../NATIVE_SECURITY.md), [desktop installation](../../LINUX_DESKTOP_TESTING.md) and [ADR-004](../../decisions/ADR-004-linux-persistence-and-production.md). The final test/artifact index below records only executed checks; historical results are not reused as production passes.

## Automation scope

An additional process-observer run against the externally automated editor failed its distinct-network-namespace assertion. This result is retained and not made to pass by weakening the observer. Matching WebKitGTK 2.52.6 source establishes that WebDriver injects WEBKIT_INSPECTOR_SERVER and that a nonempty inspector server makes bubblewrap preserve networking for the transport. The live automated editor contained that inspector value and TAURI_WEBVIEW_AUTOMATION=true. The actual supervised production preview had neither an inspector variable nor enabled automation and passed the unchanged seccomp/namespace observer. Ordinary desktop launch must be observed separately without WebDriver. Direct automated ACL probes cannot establish that network sandbox boundary.
