# Real Linux native-security validation — 2026-11-17

Validation continued from `ad9e6fd` on `feat/mdx-react-engine`, for draft PR #1. These are actual Linux WebKitGTK, Tauri IPC, systemd and cgroup observations. Chromium and configuration tests are reported separately. No visual editing or product features were added.

## Environment and provenance

A task-local full-system Ubuntu 24.04.5 VM ran kernel `6.8.0-149-generic`, systemd `255.4-1ubuntu8.18`, GTK `3.24.41`, WebKitGTK/WebKitWebDriver `2.52.6`, tauri-driver `2.1.0`, Node `24.22.1` and npm `11.9.0`. It had four virtual CPUs, 8 GiB RAM, a real systemd user manager and delegated `cpu`, `memory`, `pids`, `cpuset` and `io` controllers. Application processes ran as UID 1000. Xvfb used a private Xauthority cookie, not `-ac`.

The outer cloud host lacked KVM, a usable user manager, GTK and cgroup delegation. Rootless Docker's cgroup driver was none. A QEMU TCG guest supplied its own kernel and cgroup hierarchy; no writable host cgroup mount or unrestricted preview fallback was used. Supported software-rendering options avoided llvmpipe crashes. WebKit sandbox-disable environment variables were absent. Recorded guest settings were `unprivileged_userns_clone=1`, `apparmor_restrict_unprivileged_userns=0`; hardened desktop AppArmor profiles are not claimed tested.

See [environment.log](environment.log), [guest-policy.log](guest-policy.log), [binary-hashes.log](binary-hashes.log) and the build logs. Binaries were embedded-asset debug builds, not optimized release packages:

- `native-verified-app`: core WebKit stress and window-close cases, before the editor-root navigation fix; feature `custom-protocol,security-test`.
- `native-final-test-app`: final IPC/namespace/profile suite, including the root-URL fix; feature `custom-protocol,security-test`.
- `native-final-normal-app`: full editor, browser-WASM MDX compilation, source input/save payload and unsaved rebuild tests; feature `custom-protocol` **without** `security-test`.

The static test editor controls the same production supervisor and handlers. Actual supervised children use `--preview-child`, have no capability and force automation false; external AT-SPI controls their UI. The directly automated private preview probe is only IPC/profile/iframe evidence, not resource-isolation evidence.

## Cgroup and journal evidence

[cgroup-summary.json](cgroup-summary.json) indexes exact units, sampled memory peaks, known PID identities and observed time since `start_preview` returned. That time is shorter than service age because launch/verification/input transfer precede the reply. The configured lifetime is 60 seconds; expiry assertions require both near-deadline survival and the actual journal cause.

Raw, losslessly compressed records:

- [webkit-stress.json.gz](webkit-stress.json.gz): actual WebKit stress samples and recorded OOM/expiry causes.
- [window-close.json.gz](window-close.json.gz): close/recovery membership samples.
- [supervisor-cgroups.jsonl.gz](supervisor-cgroups.jsonl.gz): independent 100 ms observation of the first trusted Rust supervisor helper run. These are helper processes, not WebKit JavaScript.
- [user-journal.log](user-journal.log) and [kernel-journal.log](kernel-journal.log): retained service termination and memcg OOM records. The immediate WebKit OOM unit is `programmable-notes-preview-5051-1794952522242864160.service`.

The journal sometimes reports `Failed to kill control group ... Invalid argument` while already exiting/OOM-killed groups are collected. Tests independently require empty/missing groups and no live known PID identity; a successful command or warning alone is never the cleanup proof. Zombie states are nonexecuting; sampled identity checks prevent PID reuse from hiding a surviving process. This does not prove containment of an arbitrary compromised native process deliberately migrating outside its group.

## Failures investigated and corrected

- **Private WebDriver attachment failed:** upstream Wry dropped explicit automation when it created the ephemeral context. The documented two-file [Wry source fork](../../../src-tauri/vendor/wry/PROGRAMMABLE_NOTES_PATCH.md) transfers unused automation without sharing profiles. Production explicitly forces automation off. Original crate checksum and licenses are retained.
- **Blank normal native editor:** Tauri used `tauri://localhost` with an empty custom-scheme path; the navigation callback rejected it. [Inspection](failed-editor-root-inspection.log) showed an empty page. [Navigation red](navigation-red.log) reproduces the rejected root; [green](navigation-green.log) verifies the narrow fix and external/unlisted URL denial. The normal editor subsequently compiled and rebuilt real MDX.
- **Slow software WebKit startup:** the 20-second external accessibility wait was insufficient under TCG/25% CPU. A 45-second readiness wait passed; the independent 60-second service budget was unchanged. llvmpipe rendering crashes were avoided with supported renderer options, not a sandbox switch.
- **First armed memory attempt expired at 373.2 MiB:** the OOM assertion correctly failed. [Failed log](failed-armed-pressure.log) and [samples](failed-armed-pressure.json.gz) remain. The contract's immediate-allocation fixture then produced actual cgroup OOM; expiry was never relabeled OOM.
- **WebDriver keyboard input:** a combined Control/End/text sequence generated clipboard shortcuts; literal line-feed input then failed to insert a Return. [Combined sequence](failed-combined-keys.log), [newline failure](failed-newline-input.log). Explicit modifier key-up and Return actions preserved the exact saved-source assertion and passed.
- **Screenshot output ownership:** a root-copied screenshot initially caused EACCES after the Counter passed; correcting the test-output owner allowed the entire final suite to pass. [exit-statuses.log](exit-statuses.log) retains failed attempts and successful retries.

## Other checks and remaining limits

`npm run check` passed formatting, ESLint, strict TypeScript, six Vitest tests and five Chromium browser tests ([log](repository-check.log)). Four dependency-free Rust policy tests passed ([log](rust-policy.log)). The actual native app navigation test passed after its demonstrated failing run ([final log](navigation-final.log)). Both native binaries linked successfully; full [test-feature](native-test-build.log) and [normal](native-normal-build.log) build logs retain upstream deprecation warnings.

No core Linux acceptance case remains blocked by cloud infrastructure after provisioning the VM. There is no claim of optimized release packaging, native disk-write/download correctness, non-Linux resource backends, hardened distribution profiles, GPU/display portability or arbitrary compromised-native-code containment. The Save test verifies exact Blob bytes; it deliberately does not grant or simulate a native filesystem permission. Same-user DBus/device/native-browser exploit risks still require a production OS threat review. Prototype limits are fixed policy, not performance budgets; legitimate long sessions still expire.

GitHub CI for baseline `ad9e6fd` was reported passing by the user. Current CI must be read from PR #1; local runtime evidence is separate. Production security review and a target-desktop/release-build smoke test are the next milestone; visual editing remains deferred.
